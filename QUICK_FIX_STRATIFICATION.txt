PROBLEM:
--------
Unit standards count, performance level, and marking status all showing incorrect
values (0, "Not Assessed", "Not Marked") after implementing class filtering.

ROOT CAUSE:
-----------
REGEXP pattern '^[0-9]' was matching exercise numbers like "1.2" and "3.21" as
unit standards, causing incorrect calculations.

SOLUTION:
---------
Changed REGEXP pattern to '^[0-9]{4,5}$' to match ONLY 4-5 digit unit standard
IDs (e.g., 9964, 14555), not exercise numbers (e.g., 1.2, 3.21).

TECHNICAL DETAILS:
------------------
Unit Standard IDs: 4-5 digit numbers (9964, 14555, 13958)
Exercise Numbers: Decimals (1.2, 3.21) - NOT unit standards

REGEXP Pattern:
  OLD: '^[0-9]'     → Matches ANY digit start (WRONG)
  NEW: '^[0-9]{4,5}$' → Matches ONLY 4-5 digits (CORRECT)

Extraction Logic:
  SUBSTRING_INDEX(SUBSTRING_INDEX(m.exercise, '\t', 1), ' ', 1)
  → Extracts first part before tab or space

Examples:
  "9964 - Apply health..." → "9964" → MATCH ✅
  "1.2 Draw symbols..." → "1.2" → REJECT ❌
  "3.21\tWhy is it..." → "3.21" → REJECT ❌
